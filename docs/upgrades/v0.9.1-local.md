# 基于正式 v0.9.1 的定制整合

本仓库基于 [agegr/pi-web](https://github.com/agegr/pi-web) 的正式标签 `v0.9.1`，
上游提交为 `8366762fa4b4ef3327f1b19e8ff7bf891a14c06c`。独立维护，按需同步上游更新。

公开仓库保留上游历史，将经过验证的本地定制整理为单独提交；本机部署地址、进程信息、
凭据、会话、构建目录和私有验收备份不作为公开历史的一部分。以下是可复用的整合说明，
不是某台服务器的实时部署状态。

## 保留的本地功能

1. [Token 用量统计](../token-usage.md)：按 cwd/worktree 分组、fork 去重、所有时间范围使用
   同一代快照、范围切换不重新请求、服务端后台每 30 秒刷新。它与上游的服务商余额/额度查询独立。
2. [文件编辑与管理](../workspace-files.md)：CodeMirror、UTF-8 文本手动保存、草稿保留与冲突检查，
   支持文件和文件夹的新建、重命名及确认后的永久删除；保留预览、Diff、上传下载和真实终端。
3. [Full-only 搜索策略](../adr/0004-full-only-search-tools.md)：普通会话仅在 Full 预设下启用
   搜索工具，URL Context 还要求兼容的 Gemini API；子智能体遵循自身资源策略。

仅采用正式 v0.9.1，不混入该标签之后的四项改动：新会话图标/对齐、UNC 路径处理、
`SameSite=Lax` Cookie，以及扩展弹窗标题换行。

## 合并处理

直接文本冲突集中在两处：

- `components/AppShell.tsx`：保留用量面板和文件编辑器接入，语言/主题控件跟随上游移到设置。
- `lib/rpc-manager.ts`：保留上游 `subagentResources.exactSystemPrompt` 的优先级（包括空字符串），
  同时确保本地搜索策略在扩展工具激活前安装。

`lib/rpc-startup-integration.test.mjs` 使用真实 SDK 初始化验证 Default、Read-only、Full、
Chat only、选择持久化，以及子智能体精确提示词在重载/重开后的行为；不调用模型。
主题浏览器测试改为通过设置操作控件，并覆盖新增主题下的用量入口和编辑草稿保留。

### 旧 Git 的已知兼容限制

上述两项失败均发生在 **Git 2.25.1**：该版本不支持 `rev-parse --path-format=absolute`，
而上游 `lib/worktree.ts` 依赖其输出格式。受影响的测试是：

- `lib/worktree.test.mjs`：`main and linked worktrees share one canonical project root`。
- `lib/subagent-isolation.test.mjs`：`isolated worktrees are unique, write-safe, and cleaned without deleting dirty work`。

本次整合未改写 Git 兼容逻辑，也未屏蔽测试。使用旧 Git 时，worktree 识别/操作及子智能体
worktree 隔离仍不可靠。若需要这些功能，请使用支持上述选项的 Git 版本。
Token 统计按目录分组不依赖这个解析器。

## 复验

在独立测试目录中执行，勿使用真实会话或重要项目作为破坏性测试数据：

```bash
npm ci
node_modules/.bin/tsc --noEmit
npm run lint
npm test
node --test lib/rpc-startup-integration.test.mjs lib/rpc-manager-search-policy.test.mjs lib/search-tool-policy.test.mjs
```

浏览器回归脚本位于 `e2e/`，包括 `usage.mjs`、`usage-switching.mjs`、`workspace-files.mjs`、
`themes.mjs`、`terminal.mjs` 和 `stable-integration.mjs`。先阅读各脚本的服务地址/启动模式设置，
仅连接隔离测试服务；部分脚本会进行文件修改或启动临时服务。
可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已安装的 Chromium。

发布构建请用新的构建目录，不在运行 dev 的目录执行 `npm run build`。
更新已有服务前备份配置、检查插件路径并等待智能体空闲；服务重启后网页终端需要重新打开。
